## 1. Conventions

### 1.1 Standard columns

Unless a table says otherwise, every table has these three columns. They are not repeated in the tables below.

| Column | Type | Null | Default | Key | Description |
|---|---|---|---|---|---|
| `id` | `uuid` | No | UUID v7 (generated by the app) | PK | Time-ordered unique identifier |
| `created_at` | `timestamptz` | No | `now()` | | When the row was created (UTC) |
| `updated_at` | `timestamptz` | No | `now()`, updated on save | | When the row last changed (UTC) |

History/event tables (`*_history`, `*_events`, `audit_logs`, `stock_movements`) are append-only and have no `updated_at`.

### 1.2 Naming and types

| Rule | Detail |
|---|---|
| Table names | snake_case plural, set explicitly with `db_table` (e.g. `doctor_consultations`) |
| Foreign keys | `<object>_id`; `ON DELETE` rule given in the Key column (`CASCADE`, `PROTECT` = refuse delete, `SET NULL`) |
| Money | `bigint` in **poisha** (৳1 = 100). Every money column is `≥ 0`. Currency column `char(3)` = `BDT` where money is stored |
| Enumerations | `varchar` holding an upper-case code, with a `CHECK` constraint listing allowed values (§17) |
| Translated text | Two columns: `*_en` (required where the field is required) and `*_bn` (optional, falls back to English) |
| Phone numbers | `varchar(16)` in E.164 (`+8801XXXXXXXXX`) |
| Time | `timestamptz` stored in UTC, shown in `Asia/Dhaka`; `date` for calendar dates |
| Search | `search_vector tsvector` generated column with a GIN index; `pg_trgm` GIN index on names for typo-tolerant search |
| Soft delete | Not used. Catalog-type rows are switched to `INACTIVE`; transactional rows are never deleted |
| Key column codes | **PK** primary key · **FK** foreign key · **UQ** unique · **IX** indexed · **CK** check constraint |

## 2. accounts

### 2.1 `users` — User

| Column | Type | Null | Default | Key | Description |
|---|---|---|---|---|---|
| `user_type` | `varchar(10)` | No | | CK, IX | `UserType`: PATIENT, DOCTOR, STAFF |
| `phone` | `varchar(16)` | Yes | | UQ with `user_type` | E.164 phone. Required for PATIENT and DOCTOR |
| `username` | `varchar(50)` | Yes | | UQ | Staff sign-in name. Required for STAFF |

| `status` | `varchar(25)` | No | `PENDING_VERIFICATION` | CK, IX | `UserStatus` |

Constraints: `CK (user_type = 'STAFF') = (username IS NOT NULL)`; `CK user_type = 'STAFF' OR phone IS NOT NULL`; `UQ (phone, user_type)` — the same phone may hold one patient and one doctor account.
Doctors sign in with `doctor_profiles.doctor_code`, which resolves to the user.

### 2.2 `auth_group` + `roles` — Role

`auth_group` is Django's built-in table (`id integer PK`, `name varchar(150) UQ`). `roles` extends it one-to-one (Django multi-table inheritance), so Django's permission checks keep working.

| Column | Type | Null | Default | Key | Description |
|---|---|---|---|---|---|
| `group_ptr_id` | `integer` | No | | PK, FK → `auth_group.id` CASCADE | Same id as the Django group (no `id` / `created_at` of its own) |
| `description` | `varchar(255)` | No | `''` | | What this role is for |
| `is_system` | `boolean` | No | `false` | | System roles (PATIENT, DOCTOR, SUPER_ADMIN) cannot be renamed or deleted |
| `created_at`, `updated_at` | `timestamptz` | No | `now()` | | |

### 2.3 Permission tables (Django built-in)

| Table | Columns | Description |
|---|---|---|
| `auth_permission` | `id integer PK`, `name varchar(255)`, `content_type_id FK`, `codename varchar(100)`; UQ (`content_type_id`, `codename`) | Every permission, e.g. `doctor_consultancy.assign_doctor_consultation` |
| `auth_group_permissions` | `id bigint PK`, `group_id FK → auth_group CASCADE`, `permission_id FK → auth_permission CASCADE`; UQ pair | Role ↔ permission |
| `users_groups` | `id bigint PK`, `user_id uuid FK → users CASCADE`, `group_id integer FK → auth_group CASCADE`; UQ pair | User ↔ role |
| `users_user_permissions` | Django default | Exists but unused — permissions are granted through roles only |
